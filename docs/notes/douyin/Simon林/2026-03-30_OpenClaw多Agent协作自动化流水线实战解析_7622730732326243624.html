（二）核心内容

  1. 痛点分析与平台机制洞察 初期尝试单Agent或多Agent独立运行均失败，主要面临身份混淆、文件隔离及流程断裂问题。深入分析OpenClaw机制发现，SubAgent仅默认加载agents.md和tools.md，且同一Workspace下多Agent会读取相同的agents.md导致冲突。

  2. 架构演进与最终方案 否决了嵌套管理层（Jarvis模式）和纯子类读取主Agent配置的方案。最终确立“独立Workspace+符号链接”架构：每个角色拥有独立Workspace和专属agents.md，通过符号链接将各角色产出共享至主目录，确保身份清晰且数据互通。

  3. 流水线设计与角色分工 构建创作者、批判者、执行者三层结构。具体流程为：写手创作 -> 事实/文风双审查 -> 评分者打分（阈值8.5）-> 低于阈值由修复者修正并循环，最高重试3次。强调分工明确，避免跨产品线混用审查标准。

  4. 关键配置与避坑指南 六大注意事项：1. 避免Workspace冲突，使用独立空间；2. 关闭Agent间直接通信以防冲突；3. 核心知识注入agents.md而非依赖记忆；4. 防止工具调用死循环；5. 遵守规则限制；6. 利用心跳机制监控进度。
