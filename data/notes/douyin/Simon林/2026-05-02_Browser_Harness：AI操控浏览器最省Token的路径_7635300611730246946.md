### （二）核心内容

1. **Browser Harness简介与优势**
   Browser Harness是近期上线GitHub 15天即获9400 Star的项目，仅含约592-800行Python代码。其核心优势在于专为AI设计，通过WebSocket直连Chrome内核，Token消耗远低于传统方案，且能复用用户当前的浏览器Cookie和登录状态。

2. **与其他AI操控浏览器路径对比**
   当前主流路径包括：1. Crowdin Chrome（通过扩展操作DOM，Token中等，但易连接失败）；2. Computer Use（基于截屏像素模拟，Token消耗爆炸，不建议使用）；3. Selenium（代码量数万行，非为AI设计）；4. Browser Harness（原生CDP，轻量级，专为AI定制）。

3. **技术原理与架构**
   架构简单，主要涉及四个文件。Claude Code通过CLI发送指令给Daemon，Daemon再通过CDP的WebSocket直接控制Chrome。由于大模型（LLM）已具备截图看坐标、判断状态及编写Helper函数的能力，只需让LLM连接Chrome即可实现高效控制。

4. **自我学习与经验沉淀机制**
   项目具备‘长肌肉’能力，通过agent_helps文件实现。初始为空，AI可在运行中自行编写代码填充，持续积累经验。仓库内置76个网站的操作经验（Skills），使AI上线即具备基础技能。随着使用增多，形成正反馈循环，经验可共享。

5. **实测案例与成本分析**
   实测通过Claude Code控制Chrome，调用订阅版Midjourney生成并下载图片。流程分四步：安装依赖、开启远程调试连接Chrome、执行生图、封装为技能。Token消耗对比：Computer Use需约1.5万Token，Browser Harness仅需约2000 Token，实现零API成本调用MJ。

### 2. 四种AI操控浏览器路径对比

目前AI操控浏览器有四条路径，分别是Crowdin Chrome、Computer Use、Selenium，还有Browser Harness。Crowdin Chrome是通过扩展来操纵的，扩展然后读DOM操作页面，这个token消耗是中等的，但是受限于扩展，就是我经常会连不上这个扩展。然后第二个Computer Use就不建议大家使用了，因为这个是通过截屏来看像素来模拟鼠标键盘，这个token消耗是爆炸的，大家不要用。第三个这个Selenium它是有几万行代码，不是给AI用的。然后最后就是我们的主角Browser Harness，它通过一根WebSocket，然后指点我们的Chrome内核，一共就六百行代码，是为AI而生的，Token消耗非常低，是原生的CDP。就相当于前三个是给人穿的鞋，最后一个是给AI量身定做的。

### 3. 技术原理与复用优势

接下来我讲一下这个Browser Harness的原理。Claude Code通过CLI把指令发送给了Daemon，然后Daemon呢再通过CDP的WebSocket，然后直接来控制我们的Chrome。他一共四个简单的文件，一共大概也就七八百行代码，现在迭代的版本大概七八百行代码很简单。然后它能连接你正在用的浏览器，然后你的Cookie啊、登录状态啊，就是你都登录了抖音啊、其他的一些登录状态都是完全可以复用。为什么现在Browser Harness能实现了？它不是技术变了，是前提变了。现在我们的LLM大模型呢，它能够通过截图看坐标，然后也能通过截图判断状态，然后自己还能够写Helper函数。所以我们只要让我们的LLM连接这个Chrome就够了。

### 4. 自我学习与技能积累

下一个优势呢，其实这个Browser Harness，他的优势是他能够自己长肌肉。他有个文件叫Agent Helps，它的开箱是空的，AI可以自己写代码来进行填充。在你的运行中来持续的积累他的工作的经验。然后仓库中本身带了一些Skills，就是七十六个网站的经验就是AI。现在刚开始跑的时候，已经能读取仓库里的一些经验，相当于就是带技能就上线了。第三个就是正反馈的循环，就是你跑得越多越越好用。然后你的AI能通过这个不断的使用来沉淀他这个使用的经验给大家做分享。

### 5. 实测案例与Token成本对比

之前我已经进行了全面的实测，我通过CC控制Chrome，然后让他用订阅版的Midjourney来进行出图并下载下来。这个操作流程也不复杂，就分成四步。第一步是安装，pip install claude-code uv-tools。然后第二步就是连接Chrome，这一步有一个远程调试需要打开。然后第三步是调用Midjourney生图，就是CC就能直接操控浏览器，让Midjourney来生图了。第四步，我把它封装成了一个技能。对比传统的Computer Use跟我们的Browser Harness，Computer Use大概需要这个一点五万个Token，然后Browser Harness大概需要两千就可以了。就是通过这种形式呢，我们实现了零API的成本，让你的Midjourney进行这个图片的生成。如果大家需要封装好的技能，可以看我的首页。
